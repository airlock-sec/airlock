Add the documentation site (task 8.6) and the workflow that publishes it. `site/` holds
four pages: an overview that states the attack class and the fail-closed model, usage
covering the exact command surface and the Wasm manifest flow, a rule reference, and a
trust page with every scanner-state finding and the seven Appendix B bypasses. The
design is the tactical-telemetry archetype from the industrial-brutalist skill, chosen
for a security tool because it reads as an instrument rather than a product page: dark
substrate `#0a0a0a`, phosphor ink `#eaeaea`, one hazard red `#ff2a2a` for the accent and
the exit-code band, and exactly one green element, the `#4af626` LED on the self-scan
readout. Structure is 1px compartments and a two-column grid that collapses at 980px and
760px; macro headings are heavy sans with tight tracking and micro labels are uppercase
mono. There are no gradients, no rounded corners (the only `border-radius` is the `0`
reset on the search field) and no shadows, and `tests/unit/test_site.py` asserts that
rather than trusting the stylesheet. The site fetches nothing: one stylesheet, one
script and a four-byte SVG favicon, with `default-src 'none'` as the CSP and `data:` the
only non-self source. The script is progressive enhancement only, the copy buttons and
the rule filter degrade to hidden controls without it, and every page reads and links
with JavaScript off. The rule reference and the hero counts are generated from
`rules/builtin/*.toml` into marked blocks by `scripts/build_site.py`, and
`site/data/rules.json` carries the same 22 rows (12 HIGH, 10 WARN), so the page cannot
describe a rule set the package no longer ships; the generator refuses an unregistered
rule file, an unknown severity and a missing marker with exit 2 instead of publishing a
partial reference, and `--check` exits 1 on a stale page. The site states only what is
true today: no Action, no package index release, no SARIF, six of seven bypasses closed
with B-06 pending 6.4, and a clean scan described as "nothing matched the rules that
ship" rather than "no compromise found". `.github/workflows/pages.yml` runs the
generator check, uploads `site/` and deploys it with `contents: read`, `pages: write`
and `id-token: write`, a serialized `pages` concurrency group and a `github-pages`
environment; all four actions are pinned to a commit SHA read from the API before
pinning (`actions/checkout` v7.0.1, `actions/setup-python` v7.1.0,
`actions/upload-pages-artifact` v5.0.0, `actions/deploy-pages` v5.0.1). Tests came
first: `test_build_site.py` has 11 cases over the generator, its refusals and its
determinism, and `test_site.py` has 35 over link and fragment resolution, unique ids,
`aria-current`, the CSP, one script and no inline handler or style attribute, the closed
palette and the single green, the sitemap and robots, the workflow pins, and one case
that runs `apply_patterns` and `cap_findings` over every published file so a page that
ever carries a rule match fails the suite instead of the next self-scan. Docs follow:
`project_structure.md` gains the `site/` tree, the generator in `scripts/`, the
protected-path note, the change table row and the generated-files rule, and
`CONTRIBUTING.md` tells a contributor to regenerate after a rule change. Verified
locally, Python 3.14.0 in the checked-out virtualenv while CI runs 3.11: `pytest` 709
passed with 1 skipped (46 new), `ruff check` clean, `ruff format --check` clean on 62
files, `mypy src` clean on 25 files, `scripts/build_site.py --check` exit 0, `airlock
scan --mode full .` 0 HIGH · 0 WARN · 2 INFO over 125 files with nothing skipped, and
`roadmap_progress.py --check` exit 0 with the table regenerated by the script. The row
stays `[~]` because the deployment has not been observed: Pages is not enabled on the
repository yet (`GET /repos/airlock-sec/airlock/pages` returned 404 before this change),
so enabling it with `build_type: workflow` and reading the first deployment run is the
remaining half. The layout was then read in a browser rather than only asserted: all
four pages at a 770 CSS px viewport and again through a 1440 px iframe harness over a
local static server, with no console errors or warnings. That pass changed three things
the structural assertions could not see: the change log grid wrapped six cards into five
plus one loose cell, so it is now a fixed three-column rhythm that drops to two at 980px
and one at 760px; the install terminal stretched to the height of the taller column
beside it, so a terminal is set to `align-self: start`; and the small metadata on the
red band carried `opacity: 0.85`, which is too thin for small text on a saturated
background, so it was removed. The rule filter was exercised (wasm family, then HIGH
only) and every bypass badge rendered its state. One limit stands: the headless browser
denies the clipboard write, so what was observed is the fallback path, which selects the
